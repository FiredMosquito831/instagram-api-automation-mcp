## 2. Constraint 14 exception

**Constraint 14 (`global-constraints.md`, line 14):** the event cursor is opaque; `ig_events_ack` refuses any cursor that has not been issued, and it never moves backwards.

**The exception (owner-decided, P4 fix round 2, N-14).** After a state loss, a confirmed `ig_stop_clear` starts the event cursors at zero. The next `ig_events_pending` carries a notice (`cursors_reset`). Every event in the event file is delivered again with the id it had, so an acknowledged event can come back. The consumer dedupes by event id.

- **Reason.** A missed inbound message is treated as worse than a duplicate.
- **Cost.** A redelivery after a state loss. The consumer must dedupe by id.
- **Limits of the exception.** A reset that cannot be saved is refused with `CONFIG`, nothing is delivered, and the next pending call tries again. A damaged stored acked or issued position is removed, not reset to zero, so no acked event is redelivered before the owner clears the stop. While the cursors are unknown and a stop holds, pending and ack are refused with `STOPPED`.
- **Where.** `src/events.js:13-15` (the header describing the unknown-cursor hold and the confirmed clear), `src/events.js` (the notice and the reset), `src/state.js:206-212` (cursor damage), README "Recovery from a damaged state file" (the exception is stated there), and the spec's Call P (the exception is noted there).
- **Not changed.** `global-constraints.md` still states the rule without the exception (see the question below).
